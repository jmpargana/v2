Control Flow

Lesson 6 · g8 bytecode compiler · Prev: Functions and Call Frames · Reference: Instruction Set

Until now, your VM has executed bytecode in a straight line — instruction 0, then 1, then 2. The instruction pointer only ever moves forward. Control flow changes that. An if statement means: skip some instructions. A loop means: jump backward. The tool for both is a jump instruction.

Three new concepts

1. Comparisons produce values

Before you can branch, you need a condition. A comparison like a > b needs to produce a result that the VM can test. The simplest approach for g8: comparisons produce integers — 1 for true, 0 for false. No boolean type needed.

Comparison opcodes follow the same accumulator convention as arithmetic: the left operand is in a register, the right operand is in the accumulator, and the result (0 or 1) overwrites the accumulator.

OpcodeOperationV8 equivalent
OpTestEqualacc = (reg == acc) ? 1 : 0TestEqual
OpTestLessThanacc = (reg < acc) ? 1 : 0TestLessThan
OpTestGreaterThanacc = (reg > acc) ? 1 : 0TestGreaterThan

The compilation of a > b is identical to a + b — compile left, stash, compile right, emit operator. The only difference is which opcode.

2. Conditional jumps

A jump changes the instruction pointer to a different position in the bytecode. A conditional jump does so only if a condition is met.

OpcodeOperandWhat it does
OpJumpIfFalse offset (1 byte) If acc == 0, advance ip by offset bytes. Otherwise, continue.
OpJump offset (1 byte) Unconditionally advance ip by offset bytes.

The offset is relative — it's added to the current ip, not an absolute address. This means the jump is "skip forward N bytes," not "go to byte N." V8 uses relative offsets too.

Why relative? If you insert or remove instructions before the jump, absolute addresses break. Relative offsets are local — the jump only needs to know the distance to its target, not where it sits in the overall program. This makes backpatching (below) simpler.

3. Backpatching

Here's the problem: when the compiler emits JumpIfFalse at the start of an if statement, it doesn't yet know how many bytes the then-branch will be. It can't write the offset yet. The solution is backpatching:

  1. Emit JumpIfFalse with a placeholder offset of 0
  2. Remember the position of that placeholder
  3. Compile the then-branch
  4. Now you know how far ahead the else-branch starts
  5. Go back and patch the placeholder with the real offset
// In the compiler:
func (p *Program) emitJump(op ByteCode) int {
    p.code = append(p.code, byte(op), 0) // placeholder
    return len(p.code) - 1               // index of the placeholder byte
}

func (p *Program) patchJump(placeholder int) {
    offset := len(p.code) - placeholder - 1
    p.code[placeholder] = byte(offset)
}

emitJump writes the opcode and a 0 placeholder, then returns the index of that 0. patchJump calculates the distance from the placeholder to the current end of code, and overwrites the 0.

Compiling if/else

The pattern for if (cond) { then } else { alt }: 

compile(condition)         // acc = 0 or 1
jumpIfFalse = emitJump(OpJumpIfFalse)
                           // placeholder → skip to else
compile(then-branch)
jump = emitJump(OpJump)   // placeholder → skip over else
patchJump(jumpIfFalse)    // now we know where else starts
compile(else-branch)
patchJump(jump)            // now we know where end is

The two jumps work together: JumpIfFalse skips the then-branch if the condition is false. Jump at the end of the then-branch skips the else-branch (so you don't fall through into it).

Worked example

Source:

function max(a, b) {
    if (a > b) {
        return a;
    } else {
        return b;
    }
}
let result = max(5, 3);

Bytecode for max

// params: a=r0, b=r1

// Compile condition: a > b
0000  Ldar   r0          // acc = a
0002  Star   r2          // r2 = a (stash for >)
0004  Ldar   r1          // acc = b
0006  TestGT r2          // acc = (r2 > acc) = (a > b) ? 1 : 0

// Conditional jump
0008  JumpIfFalse 6      // if acc==0, skip 6 bytes → go to 0010

// Then branch: return a
000a  Ldar   r0          // acc = a
000c  Return

// Jump over else (not reached if we returned, but needed
// if the then-branch didn't return)
000e  Jump   4           // skip 4 bytes → go to 0014

// Else branch: return b
0010  Ldar   r1          // acc = b
0012  Return
Note on the Jump at 000e: In this example both branches return, so the Jump is never reached. But the compiler doesn't analyze whether branches return — it always emits the jump. Dead code elimination is an optimization pass, not the compiler's job.

The VM changes

The new handlers are short:

case OpTestEqual:
    r := frame.bytecode.Code[frame.ip]; frame.ip++
    if frame.regs[r] == vm.acc { vm.acc = 1 } else { vm.acc = 0 }

case OpTestLessThan:
    r := frame.bytecode.Code[frame.ip]; frame.ip++
    if frame.regs[r] < vm.acc { vm.acc = 1 } else { vm.acc = 0 }

case OpTestGreaterThan:
    r := frame.bytecode.Code[frame.ip]; frame.ip++
    if frame.regs[r] > vm.acc { vm.acc = 1 } else { vm.acc = 0 }

case OpJumpIfFalse:
    offset := frame.bytecode.Code[frame.ip]; frame.ip++
    if vm.acc == 0 {
        frame.ip += int(offset)
    }

case OpJump:
    offset := frame.bytecode.Code[frame.ip]; frame.ip++
    frame.ip += int(offset)

Notice: the ip has already advanced past the opcode and the operand byte when the jump executes. The offset is relative to that position — the byte after the jump instruction. That's what patchJump computes.

The grammar extension

You need to add to your parser:

IfStmt := "if" "(" Expr ")" "{" Stmt* "}" ("else" "{" Stmt* "}")?

And three new comparison operators in expression parsing. The simplest approach: add them at a new precedence level between Expr (additive) and Term (multiplicative): 

Expr     := Compare
Compare  := Additive (("==" | "<" | ">") Additive)?
Additive := Term ("+" Term)*
Term     := Factor ("*" Factor)*

Comparisons don't chain (a < b < c is not valid), so use ? not * — at most one comparison operator per expression.

Now implement it

  1. Lexer: Add tokens for ==, <, >, if, else. Note: = is already ASSIGN, so == needs lookahead (peek at the next character).
  2. AST: Add an IfStmt node (condition Expr, then []Stmt, else []Stmt). Add comparison ops to your Op enum (or use a separate CmpOp).
  3. Parser: Add parseIfStmt and a comparison precedence level.
  4. Opcodes: Add OpTestEqual, OpTestLessThan, OpTestGreaterThan, OpJumpIfFalse, OpJump.
  5. Compiler: Implement emitJump and patchJump. Compile IfStmt using the two-jump pattern.
  6. VM: Add the five new opcode handlers.
  7. Test: function max(a, b) { if (a > b) { return a; } else { return b; } } — test with max(5, 3) → 5 and max(2, 7) → 7.
