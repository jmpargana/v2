Tagged Values and the Heap

Lesson 7 · ~25 min · Prerequisite: Lesson 6

Your VM speaks one language: i64. Every register, every constant, every accumulator value is a 64-bit signed integer. That was enough for arithmetic, variables, functions, and control flow. But to build an isolate, you need strings, objects, arrays, booleans — all fitting through the same register-width slot.

This lesson introduces tagged pointers — V8’s technique for packing different value types into a single machine word. It also introduces the heap — the byte array that will become the core of your isolate.

The Trick: Steal a Bit

Every value in your VM will be a u64. The lowest bit is a type tag that tells you what the remaining 63 bits mean: 

Smi (small integer):
  ┌──────────────────────────────────────────────────────────────┬───┐
  │  63-bit signed integer value                                 │ 0 │
  └──────────────────────────────────────────────────────────────┴───┘
                                                              tag bit

Heap object pointer:
  ┌──────────────────────────────────────────────────────────────┬───┐
  │  63-bit heap offset                                          │ 1 │
  └──────────────────────────────────────────────────────────────┴───┘
                                                              tag bit

One AND instruction checks the type. One shift extracts the payload. This is the cheapest possible type discrimination — a single bit test.

Why the lowest bit? Heap objects are always allocated at even byte offsets (at minimum 2-byte aligned). Real offsets never have bit 0 set, so V8 repurposes it as a free tag bit. V8 calls this the Smi tag (0) and the HeapObject tag (1). You’ll find them defined as kSmiTag and kHeapObjectTag in V8’s include/v8-internal.h.

Encoding and Decoding

Smis

To store integer 42 as a tagged value:

encode:  42 << 1 = 84
         binary: ...0101_0100
                          tag bit ─┘    (0 = Smi)

decode:  84 >> 1 = 42
         (arithmetic shift — preserves sign for negatives)

Heap Objects

To store a pointer to heap offset 16:

encode:  (16 << 1) | 1 = 33
         binary: ...0010_0001
                          tag bit ─┘    (1 = HeapObject)

decode:  33 >> 1 = 16

Both types decode with a right-shift by one. The tag bit is what you check first to know which kind of value you’re holding.

The Heap

If a tagged value says “heap object at offset 16” — offset into what? Into a Vec<u8> owned by the VM. This byte array is the heap. Every heap-allocated object is a contiguous slice of it.

Each object starts with a type byte (what kind of object?), followed by type-specific data. Here’s what two strings look like in the heap: 

Heap bytes:

  offset 0:  [0x01] [05 00 00 00] [68 65 6C 6C 6F]
              │      │              └── "hello" (UTF-8)
              │      └── length: 5 (u32 little-endian)
              └── type: String (0x01)

  offset 10: [0x01] [05 00 00 00] [77 6F 72 6C 64]
              │      │              └── "world" (UTF-8)
              │      └── length: 5
              └── type: String (0x01)

A tagged value pointing to "hello" is (0 << 1) | 1 = 1. A tagged value pointing to "world" is (10 << 1) | 1 = 21.

From Here to Isolates

Here’s the key insight:

pub struct Isolate {
    vm: VM,
    heap: Heap,
}

An isolate is a VM that owns its own heap.

A tagged value with bit 0 = 1 means “look at offset X in my heap.” Two isolates can hold the same offset number, but they point into different Vec<u8> arrays. Their worlds don’t overlap. 

Isolate A                         Isolate B
┌─────────┐                       ┌─────────┐
│  VM     │                       │  VM     │
│  acc: 1 │─ ─ ─ ┐               │  acc: 1 │─ ─ ─ ┐
└─────────┘      ▼               └─────────┘      ▼
┌──────────────────┐             ┌──────────────────┐
│ Heap A           │             │ Heap B           │
│ offset 0: "foo"  │             │ offset 0: "bar"  │
└──────────────────┘             └──────────────────┘

Same tagged value (1), completely different data.

No shared mutable state. No cross-isolate pointer chasing. No GC coordination between isolates. This is how V8 runs multiple JavaScript contexts — tabs, workers, extensions — inside a single OS process without them interfering with each other.

Why can’t two isolates share tagged values that point to heap objects?
Tagged values are encrypted per isolate
Heap offsets index into different byte arrays
Each isolate uses a different tag bit convention
Smis have different encodings per isolate

Implementation

Your task: create the Value type and Heap struct, then migrate your VM from i64 to Value. All 19 existing tests should still pass — every current value is a Smi under the hood.

Step 1: src/value.rs

Create a newtype over u64:

#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct Value(u64);

impl Value {
    const TAG_MASK: u64 = 1;

    // Smi: encode by shifting left 1 (tag bit = 0)
    pub fn from_smi(n: i64) -> Value { ... }
    pub fn is_smi(self) -> bool { ... }
    pub fn as_smi(self) -> i64 { ... }

    // Heap: encode by shifting left 1 and setting tag bit
    pub fn from_heap(offset: usize) -> Value { ... }
    pub fn is_heap_object(self) -> bool { ... }
    pub fn heap_offset(self) -> usize { ... }
}

Default is important — Value(0) is Smi 0, which lets you initialize [Value; 256] register arrays.

Tests to write:

  • Round-trip positive Smi: Value::from_smi(42).as_smi() == 42
  • Round-trip negative Smi: Value::from_smi(-7).as_smi() == -7
  • Round-trip zero: Value::from_smi(0).as_smi() == 0
  • Smi discrimination: Value::from_smi(42).is_smi() == true
  • Round-trip heap offset: Value::from_heap(16).heap_offset() == 16
  • Heap discrimination: Value::from_heap(16).is_heap_object() == true
  • Smi is not heap: Value::from_smi(42).is_heap_object() == false

Step 2: src/heap.rs

Create the heap — a byte array with typed object allocation:

pub struct Heap {
    bytes: Vec<u8>,
}

#[repr(u8)]
pub enum InstanceType {
    String = 1,
}

impl Heap {
    pub fn new() -> Self { ... }

    pub fn alloc_string(&mut self, s: &str) -> Value {
        let offset = self.bytes.len();
        self.bytes.push(InstanceType::String as u8); // type byte
        let len = s.len() as u32;
        self.bytes.extend_from_slice(&len.to_le_bytes()); // 4 bytes
        self.bytes.extend_from_slice(s.as_bytes());        // payload
        Value::from_heap(offset)
    }

    pub fn read_string(&self, val: Value) -> &str { ... }
}

For read_string: get the heap offset from the value, assert the type byte is InstanceType::String, read the 4-byte length, then slice the UTF-8 bytes.

Tests to write:

  • Allocate a string, read it back, verify contents match
  • Allocate two strings, verify they produce different Values
  • Verify the returned values are heap objects (.is_heap_object())

Step 3: Migrate the VM

Change i64 to Value across your VM and compiler:

BeforeAfter
acc: i64acc: Value
reg: [i64; 256]reg: [Value; 256]
cons: Vec<i64>cons: Vec<Value>
self.acc += regValue::from_smi(self.acc.as_smi() + reg.as_smi())

Arithmetic and comparison opcodes unwrap with .as_smi(), compute, then wrap the result with Value::from_smi(). The compiler wraps constants with Value::from_smi() when building the constant pool.

Primary source: V8’s tagged value implementation lives in include/v8-internal.h — search for kSmiTag, kHeapObjectTag, and kSmiTagMask. For the bigger picture, read the Pointer Compression in V8 blog post, which explains how V8 evolved from 64-bit tagged pointers to compressed 32-bit ones.
