Building the Virtual Machine

Lesson 2 · g8 bytecode VM · Prev: AST to Stack Bytecode · Reference: Instruction Set

Bytecode is just bytes in an array. It doesn't do anything until something reads those bytes and acts on them. That something is a virtual machine — a loop that fetches an instruction, decodes it, and executes it. Over and over, until the program is done.

The fetch-decode-execute cycle

Every CPU works this way. Your VM is a software CPU. It has three pieces of state:

StateWhat it is
ip (instruction pointer) An index into the Code array. Points at the next byte to read.
stack A slice of int. Operands and intermediate results live here.
program The Program from the compiler — the Code bytes and Constants pool.

The loop does three things on each iteration:

  1. Fetch — read the byte at Code[ip], advance ip
  2. Decode — interpret that byte as an opcode (a switch statement)
  3. Execute — do what the opcode says (push, pop, compute)
for vm.ip < len(program.Code) {
    opcode := OpCode(program.Code[vm.ip])
    vm.ip++

    switch opcode {
    case OpPush:
        // fetch the operand (next byte = constant pool index)
        // push the constant
    case OpAdd:
        // pop two, push sum
    case OpMul:
        // pop two, push product
    }
}
// result is the single value left on the stack
The IP always points ahead. The moment you read a byte, you advance past it. By the time you're inside a case body, ip already points at the next instruction (or at the operand, for OpPush). This matters when an instruction has operand bytes — you read those by advancing ip again.

Source: Crafting Interpreters, Ch. 15

Stack operations

The stack is just a Go slice. You need two operations: 

func (vm *VM) push(value int) {
    vm.stack = append(vm.stack, value)
}

func (vm *VM) pop() int {
    n := len(vm.stack) - 1
    val := vm.stack[n]
    vm.stack = vm.stack[:n]
    return val
}

That's it. In a production VM you'd use a fixed-size array for cache locality and avoid slice header overhead, but a slice is correct and clear for now.

Instruction handlers

Each opcode has a handler. Yours have three:

OpPush

OpPush has a one-byte operand: the constant pool index. Read it by fetching the next byte and advancing ip again: 

case OpPush:
    idx := program.Code[vm.ip]
    vm.ip++
    vm.push(program.Constants[idx])

Two bytes consumed total: the opcode, then the operand. This is a variable-length instruction — OpPush is 2 bytes while OpAdd and OpMul are 1 byte each.

OpAdd and OpMul

Both work the same way: pop two values, compute, push the result. The only difference is the operation. 

case OpAdd:
    b := vm.pop()  // right operand (pushed second, so popped first)
    a := vm.pop()  // left operand
    vm.push(a + b)

case OpMul:
    b := vm.pop()
    a := vm.pop()
    vm.push(a * b)
Pop order matters. The right operand was pushed last (it was compiled second), so it's on top of the stack — it gets popped first. For addition and multiplication this doesn't matter (they're commutative), but it will matter the moment you add subtraction or division. Build the habit now.

Putting it all together

Here's the complete VM. It's about 40 lines:

type VM struct {
    ip    int
    stack []int
}

func Run(program *Program) int {
    vm := &VM{}

    for vm.ip < len(program.Code) {
        op := OpCode(program.Code[vm.ip])
        vm.ip++

        switch op {
        case OpPush:
            idx := program.Code[vm.ip]
            vm.ip++
            vm.push(program.Constants[idx])

        case OpAdd:
            b := vm.pop()
            a := vm.pop()
            vm.push(a + b)

        case OpMul:
            b := vm.pop()
            a := vm.pop()
            vm.push(a * b)
        }
    }

    return vm.pop()
}

func (vm *VM) push(v int) {
    vm.stack = append(vm.stack, v)
}

func (vm *VM) pop() int {
    n := len(vm.stack) - 1
    v := vm.stack[n]
    vm.stack = vm.stack[:n]
    return v
}

Now implement it

If you haven't already implemented the Compile function from Lesson 1, now is the time — you need bytecode to feed the VM.

Add the VM and Run to your bytecode.go (or a new vm.go), then write an end-to-end test: 

func TestEndToEnd(t *testing.T) {
    input := "30 + (20 * 40)"

    // Lex
    var l Lexer
    tokens := l.Lex(input)

    // Parse
    p := New(tokens)
    ast := p.Parse()

    // Compile
    program := Compile(ast)

    // Run
    result := Run(program)

    if result != 830 {
        t.Errorf("got %d, want 830", result)
    }
}

When that passes, try a few more: 5 + 3 (→ 8), 2 * (3 + 4) (→ 14), 42 (→ 42, a bare integer with no operators).

What's next

You now have the full pipeline: source → tokens → AST → bytecode → result. The next step depends on where you want to go:

  • Add a disassembler — a function that prints bytecode in human-readable form. Invaluable for debugging as the language grows.
  • Grow the language — add subtraction, division, variables, or let-bindings. Each one teaches you something new about bytecode design.
  • Understand V8's model — how Ignition uses registers and an accumulator instead of a stack, and what that means for your compiler.
